# Handoff prompt examples (abbreviated)

These show **shape and tone**, not full specs.

---

## Tour — visibility rule (good)

**Header Tour button** appears when ALL are true:
- User is not in profile/benchmark onboarding wizard
- User has not completed the tour within the last 24 hours
- Header tour is enabled (disabled while Overview is in its initial build sequence until user skips or starts from the ready prompt)

## Tour — visibility rule (bad)

```tsx
{!isProfileWizard && !tourTaken && headerTourEnabled && (
  <HeaderTourBtn className="header-tour-btn" />
)}
```

---

## Usage — calculation (good)

**Credits remaining this month** = plan monthly allowance minus sum of all credit deductions recorded this calendar month, never below zero. Top-up balance is separate until monthly is exhausted.

## Usage — calculation (bad)

Display `{totalRemaining}` in the stat card where `totalRemaining = monthlyRemaining + topUpRemaining`.

---

## Initiatives — storage (good)

When the user accepts a suggested initiative, create an active initiative with title and description copied from the suggestion, default status "planned", and link it to the track/category it came from.

## Initiatives — storage (bad)

INSERT INTO initiatives (title, description, status, track_id) VALUES (...)

---

## AI analysis — handoff requirement (good)

When the brief page shows **Cohort position** under **Fuel analysis**, the handoff includes:
- Input JSON assembled from snapshot rows + profile + founder narrative
- Output JSON with a paragraphs array
- Full system prompt (third-person, no invented metrics)
- Full user prompt template (insert serialized input)
- Backend: validate, call model, cache by company + benchmark period; frontend: loading skeleton, render paragraphs, fallback message on failure

## AI analysis — handoff requirement (bad)

"Cohort position is generated by AI from benchmark data." (no prompt, no JSON contract, no cache rules)
